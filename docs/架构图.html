系统架构：一次请求经过哪些层

通过 nginx 访问时，页面和 API 同源；Vite 开发模式通过代理保持同源。后端不保存登录 Session，验证 JWT 后仍查询用户状态和角色。报名一致性依赖 MySQL 事务、课程行锁与唯一索引，可支持多个后端副本。

权限在两处生效

前端路由守卫只决定显示哪些页面；真正的拦截在后端：Security 过滤链校验 JWT，管理员接口再用 @PreAuthorize 检查角色。

名额为什么不会超卖

同一门课的报名、取消、改容量和完成操作先锁课程行。管理员完成操作还会在锁课程后，以 FOR UPDATE 当前读报名记录，避免缓存或旧快照覆盖最新状态。

错误格式统一

业务错误经全局异常处理返回 {code, message, details}。认证失效时前端清理登录态并跳转；登录密码错误的 401 BAD_CREDENTIALS 只显示提示。

限流按前端副本分别计数

每个 nginx Pod 对登录和注册共用按 IP 计数的漏桶：速率 30 请求/分钟，burst=20 nodelay，超限返回 429。两个 Pod 不共享计数，不是整个集群每分钟最多 30 次。

线上架构：一台服务器上的单节点 K8s

按部署文档，集群运行在一台火山引擎服务器上。应用的 Pod、Service、Secret 和 PVC 属于 tcms 命名空间；Node、PV、StorageClass 是集群级资源。业务入口为 30080，SSH 22 用于管理；实际安全组放行范围须在云平台核验。

内存配置不等于实际占用

常驻业务容器的内存 limits 合计 2.75Gi：MySQL 1Gi、后端 768Mi × 2、前端 128Mi × 2。滚动更新新增 Pod、备份任务、系统和控制平面还需额外预算，应结合监控判断余量。

滚动更新与可用性边界

前后端配置 maxUnavailable: 0、maxSurge: 1，并在终止前等待 5 秒，为流量摘除留时间。是否无中断仍取决于资源余量、探针及版本兼容；单节点和单副本 MySQL 不具备主机故障高可用。

已知风险

没有域名和 HTTPS，登录密码明文传输，目前只适合内部验收和演示。数据卷和备份卷在同一块盘上，需要定期把备份下载到本地，并开云盘快照。

存储保留与备份清理

Retain 避免删除 PVC 时自动回收底层数据，但重新挂载仍需人工处理，也不能防止磁盘损坏。备份按 find -mtime +7 每日清理，不是精确的 7 天窗口；PVC 的 5Gi 是申请值，不应当作本地目录的硬配额。

密码格式变更需考虑版本兼容

新版支持 PBKDF2 和旧 BCrypt，旧版无法验证新格式密码。首次升级应避免不兼容版本同时处理认证或改密；回滚也需保留新格式校验能力，滚动更新配置不会自动解决此问题。

本地密钥会以 Secret 进入集群

secret.env 原文件留在开发机，内容会写入 Kubernetes Secret 并注入容器。Secret 的 base64 编码不是加密；是否启用静态加密取决于集群配置，不能理解成“密码只在本机”。

发布流程：.\deploy\deploy.ps1 做了什么

  1. 准备密钥文件不存在时生成 secret.env（随机密码）；应备份并复用。重新生成该文件不会自动修改已有 MySQL 数据卷中的账号密码，配置与数据库需保持一致。
  2. 构建镜像在开发机上用 Docker 构建 linux/amd64 镜像；默认标签取 Git commit，工作区有改动时追加 -dirty-时间戳，也可用 -Tag 指定。前端执行类型检查和构建，后端打包使用 -DskipTests。
  3. 交付镜像：支持两种方式未配置 Registry 时：docker save → scp → 服务器 ctr -n k8s.io images import，适用于当前单节点。指定 -Registry 时推送镜像仓库，由集群使用 registry-pull 拉取。docker.io 不可达不代表其他仓库不可用。
  4. 渲染并应用 YAML 清单本地 Kustomize 合并 base 与 prod 配置，注入镜像标签并生成 Secret；上传后执行 kubectl apply -f ~/tcms-release.yaml，等待 MySQL、后端和前端更新就绪。YAML 描述资源，镜像 tar 用于导入 containerd；含密钥的本地及远端临时清单用完删除。
  5. 检查入口和认证链路请求首页，再确认未登录访问 /api/auth/me 返回 401。这是基础冒烟检查，不等于完整业务验证；失败只给出警告，不自动回滚。

-DryRun 不构建、不连接服务器，但仍可能生成本地 secret.env 和发布配置；-SkipBuild 跳过构建及镜像交付，要求目标镜像已存在。脚本不会在每次发布前自动备份数据库。具体行为见 deploy.ps1。
