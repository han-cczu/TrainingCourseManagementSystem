## 2. 如何复现

从全新克隆开始，按以下步骤即可复现全部自测：

```powershell
git clone https://github.com/han-cczu/TrainingCourseManagementSystem.git
cd TrainingCourseManagementSystem

# 1. 后端测试（需要 Docker 运行中，Testcontainers 会自动启动 MySQL）
cd backend; .\mvnw.cmd test; cd ..

# 2. 前端类型检查和构建
cd frontend; pnpm install; pnpm build; cd ..

# 3. 启动全栈（--wait 会等到后端健康检查通过）
docker compose -f deploy/docker-compose.yml up -d --build --wait

# 4. UI 自测（首次需要下载 Chromium）
cd e2e; npm install; npm run setup; npm run all
```

- 本地默认管理员账号是 `admin` / `Admin12345`。员工账号由脚本自动注册，用户名带时间戳后缀，所以可以重复执行。
- `npm run all` 会依次执行 PR3、PR4、PR5、PR2 的自测。PR2 最后一步会触发登录限流，所以放在最后执行；之后约 1 分钟内同一 IP 不能登录。
- 每一步的截图保存在 `e2e/shots/`；失败时会自动给所有页面截图，文件名以 `FAIL-` 开头。

## 6. 并发测试结果（扩展任务的关键）

所有线程用 `CountDownLatch` 同时起跑，直接调用 Service，让竞争尽可能激烈。每个场景跑 3 次，3 次结果完全一致：

```
[ConcurrencyIT] 20 users / 5 seats: {SUCCESS=5, COURSE_FULL=15}, enrolled_count=5
[ConcurrencyIT] same user x10 clicks: {SUCCESS=1, ALREADY_ENROLLED=9}
[ConcurrencyIT] 3 cancels + 12 enrolls on 3 seats: {SUCCESS=6, COURSE_FULL=9}, enrolled_count=3
```

每次还会额外断言：`course.enrolled_count` 等于实际占名额的报名记录数（ENROLLED + COMPLETED），并且不超过容量。实现原理见技术设计 §6：先锁住课程行，再加唯一索引兜底。
