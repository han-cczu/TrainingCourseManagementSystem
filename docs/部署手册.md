# 部署手册（生产环境）

适用环境：火山引擎云服务器 `101.96.237.10` 上的单节点 Kubernetes（环境说明见 [技术设计 §9.2](技术设计.md#92-生产环境)）。

除了标明「**在服务器上执行**」的命令，其余都在**你自己的 Windows 电脑**上、项目根目录 `D:\TrainingCourseManagementSystem` 下执行。

```
浏览器 ──▶ 101.96.237.10:30080（NodePort，安全组只放行这个端口）
            └─▶ frontend：nginx ×2，托管页面，并把 /api 转发给后端
                  └─▶ backend：Spring Boot ×2
                        └─▶ mysql：StatefulSet ×1，数据卷用 local-path-retain 存储类
```

---

## 1. 一次性准备

### 1.1 配置 SSH 免密登录（强烈建议）
部署脚本要连接服务器好几次，不配免密的话每次都要输入密码。

```powershell
ssh-keygen -t ed25519        # 一路回车；已经有密钥可以跳过
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@101.96.237.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
ssh root@101.96.237.10 hostname    # 不再提示输入密码、并输出 k8s-lab，就说明配好了
```

### 1.2 火山引擎安全组放行 30080
控制台 →「云服务器」→ 找到这台实例 →「安全组」→「入方向规则」→ 添加一条规则：

| 协议 | 端口 | 源地址 |
|---|---|---|
| TCP | 30080 | `0.0.0.0/0`；如果只给公司内部使用，填公司的出口 IP |

**不要**开放 3306、6443，也不要开放整个 30000–32767 端口段。

### 1.3 选择镜像交付方式（二选一）

**方式 A：阿里云 ACR 个人版（推荐）**

1. 打开阿里云控制台 →「容器镜像服务 ACR」→ 创建个人实例（需要实名认证）。地域选「华北2（北京）」，离火山引擎北京机房近。
2. 设置 Registry 登录密码，然后新建命名空间 `tcms`，仓库类型选「私有」。
3. 在「访问凭证」页面复制公网地址，格式类似 `crpi-xxxx.cn-beijing.personal.cr.aliyuncs.com`。
4. 在电脑上登录：
   ```powershell
   docker login crpi-xxxx.cn-beijing.personal.cr.aliyuncs.com
   ```
5. **在服务器上执行**，创建集群拉取镜像用的密钥。用 `read -s` 输入密码，密码不会留在命令历史里：
   ```bash
   kubectl create namespace tcms --dry-run=client -o yaml | kubectl apply -f -
   read -rp 'ACR 用户名: ' U; read -rsp 'ACR 密码: ' P; echo
   kubectl -n tcms create secret docker-registry registry-pull \
     --docker-server=crpi-xxxx.cn-beijing.personal.cr.aliyuncs.com \
     --docker-username="$U" --docker-password="$P"
   unset U P
   ```

> ACR 个人版免费，但官方定位是开发测试用、没有 SLA。如果以后要正式生产使用，可以换成火山引擎镜像仓库 CR（收费，和服务器同一家云，拉取最快），换的时候只需要改 `-Registry` 参数和上面的拉取密钥。

**方式 B：不使用镜像仓库**

不用做任何准备。部署脚本会把镜像打包、上传到服务器后直接导入，每次大约上传几百 MB。只适合单节点集群。

### 1.4 密钥文件 secret.env
第一次运行部署脚本时，会自动生成 `deploy/k8s/overlays/prod/secret.env`，里面有随机的数据库密码、JWT 密钥和管理员初始密码。管理员初始密码会**在屏幕上打印一次**。

- 这个文件不会提交到 Git。**请把它备份到安全的地方**，比如密码管理器。文件丢了再重新生成的话，新密码和数据库里已有的密码就对不上了。
- MySQL 只在第一次初始化数据卷时读取密码。之后再改 `secret.env` 里的数据库密码不会自动生效，需要先进 MySQL 修改密码。
- 如果要手动编辑这个文件，请保存为 **LF 换行**（VS Code 右下角可以切换）。

### 1.5 允许运行 PowerShell 脚本
如果运行脚本时提示「禁止运行脚本」，执行一次下面的命令（只影响当前用户）：
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## 2. 发布

```powershell
# 方式 A
.\deploy\deploy.ps1 -Registry crpi-xxxx.cn-beijing.personal.cr.aliyuncs.com/tcms

# 方式 B
.\deploy\deploy.ps1

# 只预览将要发布的资源（不构建、不连服务器）
.\deploy\deploy.ps1 -DryRun
```

方式 A 可以把仓库地址存成环境变量，以后只要运行 `.\deploy\deploy.ps1`：
```powershell
[Environment]::SetEnvironmentVariable('TCMS_REGISTRY', 'crpi-xxxx.cn-beijing.personal.cr.aliyuncs.com/tcms', 'User')
```

**脚本做了什么**：
1. 构建前后端镜像，标签用 Git commit 号
2. 推送到镜像仓库，或者导入到服务器
3. 在本地渲染 K8s 清单
4. 上传到服务器并执行 `kubectl apply`
5. 等待 MySQL、后端、前端都滚动更新完成
6. 删除服务器上的渲染文件（里面有密钥）
7. 访问公网地址做冒烟检查

**第一次发布**时 MySQL 要初始化数据库，大约需要 1 分钟。这段时间后端会停在 `Init:0/1`，在等 MySQL，这是正常的。

## 3. 验证

- 浏览器打开 <http://101.96.237.10:30080>
- 安全组还没放行 30080 时，用 SSH 隧道把服务器的 30080 转发到本机，窗口保持打开，然后访问 <http://localhost:18080>：
  ```powershell
  ssh -N -o ExitOnForwardFailure=yes -L 18080:127.0.0.1:30080 root@101.96.237.10
  ```
  本地端口不要用 8080：本地 docker compose 的后端占用着它，浏览器会连到本机后端，只看到一段 401 JSON。
- **在服务器上**查看状态：
  ```bash
  kubectl -n tcms get pods,svc,pvc
  kubectl -n tcms logs deploy/backend --tail=100      # 后端日志
  kubectl -n tcms get events --sort-by=.metadata.creationTimestamp | tail -20
  ```

## 4. 回滚

**在服务器上**回到上一个版本：
```bash
kubectl -n tcms rollout undo deployment/backend
kubectl -n tcms rollout undo deployment/frontend
kubectl -n tcms rollout history deployment/backend    # 查看历史版本
```

用方式 A 时，也可以用旧标签重新发布：
```powershell
.\deploy\deploy.ps1 -Registry <仓库地址> -Tag <旧标签> -SkipBuild
```

数据库迁移脚本只新增、不修改已有结构（技术设计 §9.5），所以回滚代码时不需要回滚数据库。

## 5. 备份与恢复

每天 03:00 会自动备份一次，保留 7 天（技术设计 §9.6）。

### 5.1 查看备份、手动备份（在服务器上）
```bash
kubectl -n tcms get cronjob,jobs
kubectl -n tcms create job --from=cronjob/mysql-backup mysql-backup-manual-$(date +%s)   # 立即备份一次
ls -lh /opt/local-path-provisioner/*_tcms_mysql-backup/                                  # 备份文件位置
```

### 5.2 下载到本地（建议每周一次）
备份文件和数据库在同一块磁盘上，磁盘坏了会一起丢失，所以要定期下载一份：
```powershell
New-Item -ItemType Directory -Force D:\tcms-backups | Out-Null
scp "root@101.96.237.10:/opt/local-path-provisioner/*_tcms_mysql-backup/tcms-*.sql.gz" D:\tcms-backups\
```
另外，建议在火山引擎控制台 →「云盘」里给系统盘设置自动快照策略。

### 5.3 恢复（会覆盖当前数据，在服务器上执行）
```bash
# 1. 先停掉后端，避免恢复过程中有新数据写入
kubectl -n tcms scale deployment/backend --replicas=0

# 2. 导入备份（把文件名换成要恢复的那一份）
BACKUP=$(ls /opt/local-path-provisioner/*_tcms_mysql-backup/tcms-20261105-030000.sql.gz)
gunzip -c "$BACKUP" | kubectl -n tcms exec -i mysql-0 -- bash -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'

# 3. 重新启动后端
kubectl -n tcms scale deployment/backend --replicas=2
```

### 5.4 导入演示数据（可选，会清空现有数据）
用于验收或演示前，给系统填充一套逼真的数据：约 60 名员工、28 门课程、约 590 条报名记录，内容见 [README · 演示数据](../README.md#演示数据可选)。在本机执行：

```powershell
.\deploy\demo\load-demo-data.ps1 -Target k8s     # 需要本机有 Python 3.10+；-Server 可指定其他服务器
```

脚本会依次执行以下步骤：
1. 要求输入服务器地址进行确认。
2. 手动触发一次 `mysql-backup` 备份，备份未成功就中止。
3. 在本机生成 SQL，上传到服务器，再导入 `mysql-0`。整个导入在一个事务里完成，中途出错会自动回滚。
4. 删除服务器上的临时文件。

导入会清空课程、报名和所有非管理员账号，管理员账号和密码保持不变。导入期间不需要停后端。

**注意**：
- 演示员工的密码都是 `Demo12345`，而且目前只有 HTTP（见 §7）。环境一旦交给真实用户使用，就不要再执行这个脚本。
- **撤销**：按 5.3 恢复导入前自动生成的那份备份，在备份目录里执行 `ls -t` 看到的第一个文件就是它。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 脚本停在「打包镜像并导入服务器」，日志里有 `UNPROTECTED PRIVATE KEY FILE` / `bad permissions` | Windows 自带的 OpenSSH 要求私钥只能被本人读取（用 Git Bash 生成的密钥常带有多余的继承权限），在 PowerShell 执行 `icacls $env:USERPROFILE\.ssh\id_ed25519 /inheritance:r /grant:r "${env:USERNAME}:F" "SYSTEM:F" "Administrators:F"`，然后重新运行脚本。注意方式 B 不能用 `-SkipBuild` 重跑，它会跳过镜像导入 |
| 浏览器打不开 30080 | 检查安全组有没有放行 TCP 30080；在服务器上执行 `curl -I http://127.0.0.1:30080`，能访问就说明问题出在安全组 |
| `ImagePullBackOff` | 用 `kubectl -n tcms describe pod <名称>` 查看是哪个镜像拉不下来。应用镜像（方式 A）：检查仓库地址和 `registry-pull` 密钥。MySQL 镜像：daocloud 可能在限流，在服务器上执行 `crictl pull m.daocloud.io/docker.io/library/mysql:8.4.13` 手动拉一次 |
| 后端一直是 `Init:0/1` | 在等 MySQL 就绪：执行 `kubectl -n tcms logs mysql-0` 看 MySQL 日志 |
| 后端 `CrashLoopBackOff` | 执行 `kubectl -n tcms logs deploy/backend --previous` 看上一次崩溃的日志。最常见的原因是 `secret.env` 被重新生成过，数据库密码对不上了 |
| 登录时提示「操作过于频繁」 | 触发了 nginx 的登录限流，等 1 分钟再试 |
| 想清空重来 | 不要直接删除命名空间。数据卷的回收策略是 Retain，删了命名空间数据目录还会留在 `/opt/local-path-provisioner`，但不会自动重新挂载回来，需要手动清理或按 5.3 恢复 |

## 7. 安全须知

- 目前用的是 **HTTP，没有 HTTPS**，登录密码会以明文在网络上传输。只适合内部验收和演示。正式全员使用前，需要申请域名、完成 ICP 备案，并加上 HTTPS（见技术设计 §9.4）。
- 服务器对外只开放 SSH 和 30080 两个端口；MySQL 和后端都只能在集群内部访问。
- 第一次登录后，请立即修改管理员的初始密码。
